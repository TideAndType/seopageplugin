# SEO Growth Architect

## What changed

Site Architecture is no longer primarily a picture of the URLs that already exist.

The default view is **Recommended SEO Architecture**: TideOrbit's future-state blueprint for what the site should become to cover important search intents with the smallest useful set of pages.

A separate **Current Site** toggle shows only pages that exist today.

## Evidence used

The roadmap is built from deterministic evidence already available in TideOrbit:

- existing WordPress URLs
- indexed page content and headings
- topic coverage
- search intent
- Google Search Console page/query evidence when connected
- cannibalization and consolidation signals
- orphan/unreachable pages
- click depth
- AEO readiness gaps

## Roadmap phases

Recommendations are grouped into:

- **Do now** — high-impact gaps or weak existing pages with strong evidence/demand
- **Do next** — important architecture/content improvements after the critical work
- **Later / monitor** — lower-priority supporting work

Typical actions include:

- strengthen an existing service page
- create a genuinely distinct service page
- publish a supporting informational article
- create a legitimate location page
- consolidate overlapping URLs
- connect orphan pages
- reduce click depth
- improve AI citation readiness

## Core rule

> Strengthen an existing URL before creating another one.

A new URL is justified by a materially different search task or intent, not by a keyword variation or a different suggested slug.

## User control

Drag/drop parent changes affect the **planning hierarchy only**. TideOrbit does not silently rewrite WordPress permalinks.

Consolidation remains a review workflow. TideOrbit does not automatically merge content or create a 301 redirect.
